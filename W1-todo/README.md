# todo-cli v1

第 1 周的产出物。一个能记住数据的命令行待办工具。

## 1. 如何安装

需要 Python 3.10 以上（本机是 3.12）。本项目只用标准库，**不需要 pip 安装任何东西**。

```bash
python --version    # 确认能打印出 Python 3.12.x
```

## 2. 如何运行

在**本项目目录下**打开终端：

```bash
python todo.py add "背单词"
python todo.py list
python todo.py done 1
python todo.py del 1
```

任务数据保存在同目录的 `todo.json` 里，关掉程序再打开依然在。

## 3. 当前功能

- [x] add：新增任务
- [x] list：查看全部任务（含完成状态）
- [x] done：按编号标记完成
- [x] del：按编号删除
- [x] 数据持久化到 JSON，程序重启不丢
- [x] 非法输入（空内容、非数字编号、不存在的编号）有友好提示，不崩溃
- [x] 数据文件损坏时给出警告并按空列表处理，不崩溃
- [x] 出错时退出码为 1，脚本和 CI 能判断成败（成功为 0）
- [x] 数据文件是 UTF-8（带 BOM 也行）或 GBK 都能读，从别处拷来的文件不会直接崩
- [x] 读不出来的数据文件先备份再继续，绝不被静默覆盖
- [x] 保存先写 `todo.json.tmp` 再整体替换，写失败（只读/被占用/磁盘满）只报错不崩溃，原文件保持完整

## 4. 退出码与数据安全

终端里跑完一条命令，`$LASTEXITCODE`（PowerShell）/ `%ERRORLEVEL%`（cmd）就是退出码：

```bash
python todo.py list        # 0 = 成功
python todo.py del 999     # 1 = 编号不存在
python todo.py add         # 1 = 用法错误
```

`todo.json` 读不出来时（编码不对、不是合法 JSON、顶层结构不对），程序会：

1. 打印 `[警告]` 说明原因；
2. 把原文件改名备份为 `todo.json.bad-<年月日-时分秒>`；
3. 本次按空列表继续运行。

这样做的原因是 `save_tasks` 用 `'w'` 模式写文件——一旦读失败就当空列表，
下一次 `add` 会把旧数据整片清掉。**备份是"数据不丢"的最后一道保险。**

## 5. 三个文件的分工

| 文件 | 作用 |
|---|---|
| `todo.py` | 正式版：命令行入口 + 4 个命令 + 持久化 + 异常处理 |
| `v0_最小版.py` | 20 行教学版，只演示"读 -> 改 -> 写"，数据写在 `v0_demo.json`（不碰真实数据） |
| `json_四函数.py` | `json` 模块 load/loads/dump/dumps 四个函数的演示 |
